# 🚀 0단계 - 컴포즈 기초

## 과제 진행 요구 사항

- 미션은 칸반 보드 태스크 저장소를 포크하고 클론하는 것으로 시작한다.
- 온라인 코드 리뷰 요청 1단계 문서를 참고하여 실습 환경을 구축한다.

1. 미션 시작 버튼을 클릭하여 미션을 시작한다.
2. 저장소에 GitHub 사용자 이름으로 브랜치가 생성되었는지 확인한다.
3. 저장소를 내 계정으로 포크한다.

- 기능을 구현하기 전 README.md에 구현할 기능 목록을 정리해 추가한다.
- Git의 커밋 단위는 앞 단계에서 README.md에 정리한 기능 목록 단위로 추가한다.
    - AngularJS Git Commit Message Conventions을 참고해 커밋 메시지를 작성한다.

## 1단계 기능 요구 사항

### 1. 제목 설정 기능

- 볼드체로 표시
- 1줄을 넘어가는 길이일 때 "..."으로 뒷 내용 생략

### 2. 내용 설정 기능

- 2줄 이상일 경우 "..."으로 뒷 내용 생략

### 3. 태그 설정 기능

- 태그 내용 5자까지로 제한
- 태그 개수는 5개까지로 제한
- 태그는 가로로 정렬

4. 담당자 설정 기능

- 프로필 이미지, 이름 가로로 정렬
- 1줄을 넘어가는 길이일 때 "..."으로 뒷 내용 생략
- 태그와 구분짓는 가로선 표시

5. 카드 생성 기능

- 모든 컴포넌트는 왼쪽으로 정렬
- 제목, 내용, 태그, 담당자 순으로 세로 정렬
- 컴포넌트는 인풋값이 없을 때 공간을 차지하지 않음(단 제목 컴포넌트 제외)

## 2단계 기능 요구 사항

### 1단계 피드백 반영하기

1. `Card.kt/TaskCard` 함수 `TaskInfo`의 디폴트 파라미터 값과 `nullable`에 대해 고민해보고 수정하기
    - 다음과 같이 수정했습니다! 특히, 기존에는 빈 값일 때 컴포넌트를 나타나지 않게 하고, null을 받지 않았지만 nullable로 전환하여 아무것도 전달되지 않은 상태(컴포넌트를 그리길 원치 않는 상황), 빈 문자열이 전달된 상태를 구분하고자 했습니다!

| 파라미터 | 이전                                     | 현재                            | 이유                               |
|---------|----------------------------------------|-------------------------------|----------------------------------|
| `title` | `non-nullable`, default: `emptyString` | `non-nullable`, default: `없음` | 제목은 반드시 입력받게 하기 위해               |
| `contents` | `non-nullable`, default: `emptyString` | `nullable`, default: `null`   | 본문 컴포넌트가 없는 태스크를 생성할 수 있게 하기 위해  |
| `tags` | `non-nullable`, default: `emptyList`   | `nullable`, default: `null`   | 태그 컴포넌트가 없는 태스크를 생성할 수 있게 하기 위해  |
| `contactName` | `non-nullable`, default: `emptyString` | `nullable`, default: `null`   | 담당자 컴포넌트가 없는 태스크도 생성할 수 있게 하기 위해 |

2. 코드 정렬하기(나만의 체크리스트를 만들어 PR 전에 체크하기)
    - 체크리스트:
        - [X] 모든 파일에 코드 정렬을 수행했는가?
        - [X] 해결할 수 있는 `warning`을 해결했는가?
        - [X] 사용하지 않는 `import`, `변수`, `함수`, `클래스`를 지웠는가?
3. 프리뷰가 필요한 컴포넌트에 `@Preview` 넣기

4. 모든 함수를 `public`으로 두지 않기, 굳이 `public`으로 선언할 필요가 없는 함수는 `private`으로 변경하기

5. `Modifier`를 외부에서 주입받도록 변경하기

6. 태그도 너무 길어 잘리게 되면 말줄임표(`"..."`)를 사용하여 잘렸음을 알리게 하도록 변경하기

7. 복수 파라미터를 가진 함수를 사용하는 부분에서 가독성을 위해 `named argument` 사용하기

### 단위 테스트 작성하기 
- [x] 제목에 빈 문자열이나 공백을 전달하면 예외가 발생한다.
- [x] 본문에 빈 문자열이나 공백을 전달하면 예외가 발생한다. 
- [x] 태그에 빈 리스트를 전달하면 예외가 발생한다.
- [x] 담당자 이름에 빈 문자열이나 공백을 전달하면 예외가 발생한다.
- [x] 제한된 길이에 초과되는 태그의 글자는 생략되며 말줄임표(`"..."`) 가 붙는다.

- [x] 정상적인 태그 명을 전달하면 Tag 객체가 생성된다.
- [x] 태그 명에 빈 문자열이나 공백을 전달하면 예외가 발생한다.
- [x] n개를 초과하는 태그 리스트를 전달하면 n개만 반환한다.
- [x] n글자를 초과하는 태그 명을 전달하면 n글자 뒤는 자르고 말줄임표를 붙여 반환한다.

### UI 테스트 작성하기
- [x] 전달한 제목이 화면에 표시된다.
- [x] 전달한 본문이 화면에 표시된다.  
- [x] 전달한 태그들이 화면에 표시된다.  
- [x] 전달한 담당자명이 화면에 표시된다.  
- [x] 제목과, 본문, 담당자명에 전달된 `maxLines`를 넘는 내용은 말줄임표 처리되어 항상 `maxLines`을 넘지 않는다.(해당 기능은 `Preview`로 검증)
- [x] 본문, 태그리스트, 담당자명에 `null`이 전달되면 해당 영역이 표시되지 않는다.

### 데스크톱 앱 실행 방법

1. IDE (Android Studio / IntelliJ IDEA) 활용
    1. IDE 우측 상단의 실행 구성(Run Configuration) 드롭다운 메뉴를 클릭한다.
    2. desktopRun (또는 데스크톱 아이콘이 있는 항목)을 선택한다.
    3. 재생(Run) 버튼(▶)을 누르거나 단축키(Ctrl + R 또는 Shift + F10)를 눌러 실행한다.
2. Gradle 명령어 활용
    - 터미널을 열고 프로젝트 루트 경로에서 아래의 Gradle 명령어를 직접 입력하여 실행할 수도 있다.

```agsl
./gradlew :composeApp:run
```

빌드가 완료되면 내 컴퓨터 화면 중앙에 독립된 데스크톱 창(Window)이 새로 뜨면서, commonMain에서 작성한 Compose UI가 아름답게 렌더링되는 것을 확인할 수
있다!
